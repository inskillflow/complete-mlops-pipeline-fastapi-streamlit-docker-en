Analyse this file train.py :

What is new in this version of the MLflow script?

In the previous versions, we executed one training run.  
In this version, the script executes multiple MLflow runs.

Identify in the code:

1. Where the multiple runs are defined.
2. How each run is named.
3. Which part of the code repeats the training several times.
4. How MLflow separates the results of `run1.1`, `run2.1`, and `run3.1`.

Explain why running multiple runs is useful when comparing Machine Learning experiments.

------------------------------
# Answers : 
------------------------------

- The new thing is that the script runs multiple MLflow experiments in one execution.
- The multiple runs are defined in the `CONFIGS` list:
- `run1.1`, `run2.1`, and `run3.1`.
- The `for` loop goes through this list and calls `train_one_run()` for each configuration.
- Each run gets a different name and can have different parameters such as `alpha` and `l1_ratio`.
- MLflow separates the results of each run, so we can compare their metrics, parameters, models, and artifacts later in the MLflow UI.

In simple terms: this script does not test one model configuration only. 
It tests several configurations and saves each one as a separate MLflow run.

## Question 2
--------------------------------------

Look at the code and identify the lines responsible for running multiple MLflow experiments.

In your answer, explain the role of:

- the `CONFIGS` list;
- the `for` loop;
- the `train_one_run()` function;
- `mlflow.start_run(run_name=run_name)`;
- `mlflow.end_run()`;
- `mlflow.log_params()`;
- `mlflow.log_metrics()`;
- `mlflow.sklearn.log_model()`;
- `mlflow.log_artifacts()`.

Then explain how MLflow separates the results of `run1.1`, `run2.1`, and `run3.1`.




The multiple runs are defined in the `CONFIGS` list.
The `for` loop reads each configuration and calls `train_one_run()`.
Inside `train_one_run()`, `mlflow.start_run(run_name=run_name)` starts a new MLflow run with a specific name.
Then MLflow logs the parameters, metrics, model, and artifacts for that run.
Finally, `mlflow.end_run()` closes the current run before the next one starts.
This allows MLflow to save `run1.1`, `run2.1`, and `run3.1` as separate experiments, so we can compare their results in the MLflow UI.
